= FPSOT RESTful API specification

The common rules for every HTTP API that an FPSOT specification defines: methods and status codes, resources, OpenAPI descriptions, errors, pages, versions, retries, languages, security and events.
Domain specifications, such as the registry engine, build on it.
Version 0.1 is a draft.

== Implement this spec

Read the normative text in `spec/en/` or `spec/fr/`.
Each requirement has an ID from `API-001` to `API-104`.
Check your server, your OpenAPI description and your clients against every requirement.
The rules on names and value formats come from the FPSOT naming and data types specifications.

== Adopt this spec

Read the guide in `docs/modules/en/pages/index.adoc` or `docs/modules/fr/pages/index.adoc`.
To require it in a call for tenders, ask that every API conform to this specification, version 0.1.
The comparison data in `jurisdictions/` shows how the rules compare with those of the Government of Canada and of Québec.

== Layout

[cols="1,3"]
|===
| Folder | Content

| `spec/`
| Normative text, in English and French. `book.adoc` joins the pages into one book.

| `docs/`
| Guides, in the Antora folder layout.

| `skill/`
| The agent skill: a short summary that cites requirement IDs.

| `rules/`
| Machine-checkable rules. None yet.

| `diagrams/`
| PlantUML sources and their rendered SVG files. None yet.

| `jurisdictions/`
| Comparison data per jurisdiction. `baseline.yaml` lists the compared requirements.
|===
