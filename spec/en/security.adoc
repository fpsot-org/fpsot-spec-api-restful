= Security
include::_fpsot-terms.adoc[]

Public {abbr-api-first} servers hold personal and official data, and attackers probe them every day.
These rules set the minimum that every {abbr-api} does to protect them.
The link:https://owasp.org/API-Security/editions/2023/en/0x11-t10/[OWASP API Security Top 10] of 2023 lists the risks they address.

== Transport

[[API-080]]
*API-080.* An {abbr-api} MUST serve content and accept requests only over {abbr-https-first}, with {abbr-tls-first} 1.2 or 1.3.
It MUST NOT serve content or accept a request over plain {abbr-http-first}.
A server SHOULD offer {abbr-tls} 1.3 and MUST follow link:https://www.rfc-editor.org/info/rfc9325[RFC 9325] and the documents that update it.
Over plain {abbr-http}, anyone on the network can read or change the exchange.

A server SHOULD NOT answer plain {abbr-http} at all.
Some binding rules require a redirect, such as the federal link:https://www.canada.ca/en/government/system/digital-government/policies-standards/enterprise-it-service-common-configurations/web-sites.html[configuration requirements for web sites] in Canada.
Where such a rule applies, the server MAY answer with a permanent redirect to the {abbr-https} address.
That redirect MUST use status `301` or `308`, and MUST NOT carry any content.
A redirect comes too late to protect the first request, because the client has already sent it in clear text.
A client that gets no answer learns at once to use the right address.

[[API-081]]
*API-081.* Every response MUST carry a `Strict-Transport-Security` header with `includeSubDomains`.
Its `max-age` MUST be at least 31536000 seconds, which is one year.
With the {abbr-hsts-first} header, a browser refuses any later plain connection to the host.
That protects users from an attacker who removes the encryption on a public network.

== Response headers

[[API-082]]
*API-082.* Every response MUST carry `X-Content-Type-Options: nosniff`.
A response that holds non-public data MUST carry `Cache-Control: no-store`.
Every other response SHOULD carry an explicit `Cache-Control` header.
A browser then never runs a {abbr-json-first} response as a script.
A shared cache never keeps a copy of personal data for the next user.

[[API-083]]
*API-083.* A server MUST NOT send headers that name its software or its version, such as `Server: product/1.2.3` or `X-Powered-By`.
An attacker uses a version number to pick a known flaw.

== Cross-origin requests

[[API-084]]
*API-084.* A server MUST NOT send {abbr-cors-first} headers unless a browser application on another origin needs the {abbr-api}.
When it does, it MUST allow only the origins on a fixed list.
It MUST NOT copy the `Origin` of the request into its answer.
It MUST NOT combine `+Access-Control-Allow-Origin: *+` with credentials.
An open data {abbr-api} without credentials MAY allow every origin with `+*+`.
A loose rule lets any web page read a user's data with that user's session.

== Data in requests

[[API-085]]
*API-085.* A path or a query string MUST NOT carry a secret, a token or personal information.
Servers, proxies and browsers write full addresses into logs and history, where many people can read them.
Send such values in a header or in the body instead.

[[API-086]]
*API-086.* A server MUST check every request against the schemas of the description, and MUST refuse what does not match.
It MUST set a largest body size and answer `413 Content Too Large` above it.
It MUST ignore or refuse fields that a client may not set, such as `id` or `createdAt`.
Attackers make a server that trusts its input store data it should refuse.
Fields that a client sets but should not are the mass assignment flaw.

== Access control

[[API-090]]
*API-090.* An {abbr-api} that needs to know who calls MUST accept link:https://www.rfc-editor.org/info/rfc6749[OAuth 2.0] bearer tokens.
It MUST follow link:https://www.rfc-editor.org/info/rfc9700[RFC 9700], the security best practice for OAuth 2.0.
It SHOULD use link:https://openid.net/specs/openid-connect-core-1_0.html[OpenID Connect] when it needs to know the person behind the client.
It MUST check the issuer, the audience, the expiry and the signature of every token.
This specification does not define how to sign in or how to issue tokens.
OAuth 2.0 and OpenID Connect are the shared standards of public identity services.

[[API-091]]
*API-091.* A server MUST NOT accept a secret in a query parameter.
This covers passwords, tokens and {abbr-api} keys.
A server MUST NOT give access to non-public data on the strength of an {abbr-api} key alone.
A key in an address leaks into logs.
A key without a person behind it cannot prove who acted.

[[API-092]]
*API-092.* A server MUST check, on every request, that the caller may act on the item that the request names.
It MUST also check that the caller may read or change each field of the item.
Checking only that a user signed in is the most common {abbr-api} flaw.
Any user could then read another person's record by changing an identifier in the path.

[[API-093]]
*API-093.* A server SHOULD answer `404 Not Found` rather than `403 Forbidden` when the caller may not know that the item exists.
A `403` would confirm that the item exists, which can itself be personal information.

== Rate limits

[[API-094]]
*API-094.* An {abbr-api} MUST limit the number of requests that each client can send in a period.
Above the limit, it MUST answer `429 Too Many Requests` with a `Retry-After` header.
The description MUST state the limits.
A limit protects the service from a faulty client and from a flood of requests.
It also keeps the cost of a public service under control.

[[API-095]]
*API-095.* A server SHOULD tell the client its quota with the `RateLimit-Policy` and `RateLimit` headers.
These headers come from the latest version of the Internet-Draft link:https://datatracker.ietf.org/doc/draft-ietf-httpapi-ratelimit-headers/[draft-ietf-httpapi-ratelimit-headers].
Each version of a draft expires after six months, and the next version can change the headers.
The rule stays a recommendation until the draft becomes a {abbr-rfc-first}.
A client then slows down before it reaches the limit.

== Inventory

[[API-096]]
*API-096.* An organization that runs an {abbr-api} MUST list every host and every version it exposes.
The list MUST give the description of each.
It MUST remove a version after its sunset date.
A forgotten old version keeps old flaws open long after the new version fixed them.
